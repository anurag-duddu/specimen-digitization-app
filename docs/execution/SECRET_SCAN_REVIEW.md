# Audited synthetic fixture digest findings

Reviewed 2026-09-08 UTC by release/integration. The backend-generated HTTP journey
fixture and Flutter's exact copy have identical SHA-256:
`9cc65c46bf6c2bdeff42b6186b2949197b1cba8f8b6b2869823470ed04364616`.

Files:

- `docs/execution/backend-wire-examples.json`
- `apps/specimen_digitization/test/fixtures/backend-wire-examples.json`

Detect-secrets 1.5.0 reports 33 Hex High Entropy String findings in each copy.
Each finding was parsed from JSON and verified to be exactly one 64-character
lowercase hexadecimal content/request digest in `request_digest`, `sha256`,
`ref`, or `raw_ref`. Every baseline hashed_secret was independently matched to
SHA-1 of that digest. These are synthetic request/content-addressed evidence
references, not API keys, tokens or private credentials. Fixture generation uses
the backend's local TestClient journey; no museum data or live provider output.
Architecture inspected the generated response objects; integration independently
verified exact bytes across both owner worktrees before creating this baseline.

`.secrets.baseline` contains only those individually reviewed findings, scoped to
the two exact repository paths and exact finding hashes, with `is_secret: false`.
It retains the default detector plugins, thresholds and filters generated by
version 1.5.0. The existing Flutter generated-file exclusions are unchanged.
No fixture exclusion, field regex, entropy threshold relaxation or scanner
shutdown was introduced. Fixture JSON bytes remain unchanged.

Verification in an isolated temporary Git repository: both identical files pass
`detect-secrets-hook --baseline .secrets.baseline`; adding a newly generated
credential-shaped canary under a new JSON key in each file causes rejection.
The canary has no real account/credential and was not committed. New values in
these files remain scanned; changed digest fixtures require another explicit
provenance review rather than blind baseline regeneration. Gitleaks and the
other repository secret/sensitive-path checks remain enabled.

The final fixture was recopied and parity confirmed by Flutter after additive session/lease/retry fields. Gitleaks flagged the scanner metadata key `hashed_secret`; `.gitleaks.toml` extends all default rules and allows only exact reviewed SHA-1 identifier lines AND the `.secrets.baseline` path, within the generic-api-key rule. Inline detect-secrets annotations apply only to those exact TOML identifier lines. New credential-shaped baseline values are rejected. No whole-file or global path exclusion was introduced.

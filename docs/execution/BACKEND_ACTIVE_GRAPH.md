# Bounded active evidence graph

Branch `codex/backend-reliability`, worktree `/Users/anuragduddu/.codex/worktrees/3782/specimen-digitization-app`; additive to `d6be7a0`.

Active runs exceeding 96 KiB are stored as complete immutable JSON artifacts. The database snapshot retains an indexed run summary and a scope/specimen/run/revision-bound artifact receipt. The existing 256 KiB snapshot cap applies to the complete compact snapshot, including root metadata. Original full-Run hashes remain canonical and historical inline snapshots retain their original hash semantics. SQLite graph storage persists beside its database; SQL Connect uses the configured immutable blob store.

Reads verify the stored snapshot digest, artifact size and bytes, artifact digest, canonical full-Run digest, identity links, and compact summary equality. Missing or changed evidence fails closed with an integrity conflict; it never returns the compact summary as a complete run. CAS failures may leave harmless immutable orphan blobs; no eager deletion occurs.

Supported complete graphs are bounded to 16 MiB, with 16 KiB reserved below that cap for error/control transitions during normal processing. A graph or compact snapshot that exceeds its cap is rejected before persistence. Workflow final saves and review decisions preserve the last complete graph and persist a small processing-blocked reason. Direct repository callers receive the typed size error atomically. Previously retained history remains accessible. This is bounded support, not unlimited graph storage.

Interactive workspace JSON is capped at exactly 4 MiB after serialization. A larger response returns HTTP 413 `workspace_artifact_required` with current revision, record version, authorized summary/artifact routes, artifact SHA-256/size, and `mutation_committed`. Clients must not repeat a mutation marked committed. The graph endpoint returns the exact complete `active-run-v1` envelope, with JSON media type, content length, SHA-256 header, and no-store; current membership and sensitive-source authorization apply even for historical revision access. The envelope contains the full Run; source asset and event/history routes remain separate. A read-only full evidence artifact plus summary/run controls is a valid large-record UI fallback. The ordinary workspace is not silently sampled. Serialization allocates the bounded complete workspace before rejecting an oversized wire response; this is not a streaming-memory guarantee.

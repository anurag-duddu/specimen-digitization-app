## 1. The goal and the steady state

The pipeline becomes: readers (N) -> first pass (reading units; never settles) -> field experts
(the settlement rule, in levels, with lookups and the ontology) -> a person for what is marked or
unresolved. Measured on the reference set (WP 0), the steady state is reached when all four hold
against the baseline:

1. More fields cleared right, no more cleared wrong, fewer for a person. Counted per field with the
   strict rule of the 2026-10-25 scorer (`score.py`, moved into the repository by WP 0): for a
   field the truth holds, right, wrong or review; for a field the truth says is absent, cleared,
   review or wrongly settled; every count with its denominator. A marked value counts as review,
   and its best value is reported beside it as right or wrong. "No more wrong" holds per field, not
   in total: a wrong elevation is not paid for by a fixed code. Noise rule: the baseline and every
   gate run two repeats; a gate passes when the new arm's mean right is at least the baseline's mean
   right, its mean wrong is at most the baseline's mean wrong, and every repeat of the new arm is
   within or above the baseline's two repeats for right and within or below them for wrong. The
   baseline on the 12 pilot labels is the 2026-10-25 pair arm, repeats 1 and 2
   (`~/specimen-golive/runs/free-harness-20261025/score_full.md`): primary fields 27 / 9 / 13 and
   28 / 12 / 9 right / wrong / review; fields expected absent 33 / 2 / 0 and 35 / 0 / 0 cleared /
   review / wrongly settled. The baseline on the 20 further specimens is WP 0's run of today's main.
2. Adding a reader never changes a cleared value: 0 fields cleared on different values between the
   pair arm and the three-reader arm, per repeat, in every measurement; a cleared value that
   becomes marked is reported with its cause (the spec's section 3, "What the rule gives"). The
   judge's stability: at least 90 % of units get the same `image` judgement in three repeats of the
   first pass on the reference set (units matched by label and by their readers' texts; a unit cut
   differently in a repeat is not the same unit); the units below it are reported.
3. Every settled value carries its basis (`label`, `derived`, `inferred`) and the app shows it: 0
   settled values without a basis on the reference set, and a widget test per basis.
4. Nothing dead remains: every row of section 5 is in its stated end state (removed, kept, out of
   scope, or in the work package it is deferred to), and the closing report names each row.

A gate is met or the phase stops: the gap is analysed, the work package is reworked and the
measurement is repeated. Nothing proceeds on an explanation.

## 3. Order and gates

One list, in the spec's section 7 and the plan's section 3, one lane at a time. A gate is met or the
phase stops.

Phase 0: WP 0, the reference set, its truth, the scorer and the baseline.

Phase 1, the ontology's first version and the reading units: 1.0 ontology v1 (things, fields, label
types, conventions, the code rules for the pilot's units) -> 1.1 unit record, storage, Data Connect
operation, projection field and app reader (data release before runtime) -> 1.2 first pass v2
behind `SPECIMEN_FIRST_PASS_UNITS` (units for every label, the tiling and range checks, the new
prompt variable, the transport, the ontology v1 in its prompt) -> 1.3 experts take units when the
switch is on (the settlement rule of the spec's section 3, given-up labels, a person's edits, the
ontology v1 in their instructions) -> 1.4 organiser kept and measured -> 1.5 measurement (gate:
criteria 1 and 2 met) -> 1.6 app shows the units -> 1.7 docs -> 1.8 switch on in production, then
delete the old first pass, its prompt variable, the switch, the unused field-harness prompt and the
dead `harness_knowledge` module.

Phase 2, the ontology's second version: 2.1 relations and rules (the owner's and curators' one
reading) -> 2.2 the rules baked into every model's instructions, readers included -> 2.3 code-checked
rules (the complete place chain, the elevation unit, date order, label types), the levels, the
`basis` field with its app reader -> 2.4 parts -> 2.5 organiser decision -> 2.6 measurement (gate:
criteria 1 to 3 met) -> 2.7 docs.

Phase 3, people and conventions: 3.1 people lookups, only if the owner approves a source -> 3.2 the

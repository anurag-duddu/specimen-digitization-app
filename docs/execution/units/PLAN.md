## 1. The goal and the steady state

The pipeline becomes: readers (N) -> first pass (reading units; never settles) -> field experts in
parallel (the settlement rule, lookups, the ontology) -> one check stage -> a person for what is
marked, ambiguous or unresolved. Measured on the reference set (WP 0), the steady state is reached
when all three hold against the baseline:

1. No more wrong values cleared, at least as many right values, no more fields left without a
   value; better on at least one. Scored per field by WP 0's scorer (the strict rule of the
   2026-10-25 rig's `score.py`): for a field the truth holds, right, wrong or left without a value;
   for a field the truth says is absent, cleared, left without a value or wrongly settled. Three
   conditions are gated, on totals per category (primary, derived, absent) as the baseline report
   gives them. Each is a mean over the two repeats that the baseline and every gate run, and every
   repeat of the new arm is within or better than the baseline's range (the noise rule): (a) values
   cleared wrong at most the baseline's; (b) right values (cleared right, plus marked with a right
   value) at least the baseline's right, and at least one of (a) or (b) strictly better; (c) fields
   left with no value for a person (unresolved, ambiguous, several possibilities) at most the
   baseline's. Reported, not gated: the number of marked values, and the share of specimens that
   reach a cleared disposition (`field_research/step.py:3927`), each per arm and repeat. The rule
   marks agreement-only values by design (`docs/product-requirements/PRD.md:1204`:
   "never clear on agreement alone"), so more fields carry a mark while fewer are silently wrong;
   the share of cleared specimens shows what that costs a person. Changes the rule must tolerate: an
   inferred value is marked, so the e98a924c-L2 elevation (right in the pair arm today) becomes
   marked with a right value, which counts as right in (b). The baseline is WP 0's run of today's
   code on the whole reference set, both arms, two repeats; the 2026-10-25 numbers on 12 labels
   (primary 27 / 9 / 13 and 28 / 12 / 9 right / wrong / review;
   `~/specimen-golive/runs/free-harness-20261025/score_full.md`) are context only.
2. Adding a reader changes no cleared value beyond noise. "Different value" is the scorer's
   compared value (parsed, else normalized, else literal) after its normalisation. Per repeat, the
   number of fields cleared on different values between the pair arm and the three-reader arm is at
   most the number between the pair arm's own two repeats (the noise floor; on the 2026-10-25 runs
   6 of 71 fields cleared in both pair repeats differ, and 3 of 58 between pair repeat 1 and
   three-reader repeat 1). Each pair-versus-three difference is listed with whether the image
   judgement differed between the two runs. Above the floor, the phase stops. The judge's stability
   is measured per reader-difference span from the alignment, independent of the model's
   segmentation: the verdict at each span is read off the unit covering it; stability is the share
   of spans with the same verdict in all three repeats of the first pass on the reference set; a span
   no unit covers counts as unstable; gate at least 90 %, the spans below it listed.
3. Nothing dead remains: every row of section 5 is in its stated end state, and the closing report
   names each row.

A gate is met or the phase stops: the gap is analysed, the work package is reworked and the
measurement is repeated. Nothing proceeds on an explanation.

## 3. Order and gates

One list, in the spec's section 7 and the plan's section 3, one lane at a time. A gate is met or the
phase stops.

reading) -> 2.2 the rules baked into every model's instructions, readers included -> 2.3 the check

`research_harness` package is out of this program's scope: it is kept as is, and a separate cleanup
program takes its inventory (the plan's section 5).

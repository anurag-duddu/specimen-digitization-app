# Session learnings and closeout log

This live, append-only file preserves what each Codex task learned before its
task, branch, or worktree is archived or pruned. It is the durable handoff layer
between short-lived execution contexts and the repository.

## The ritual

At the end of every repository task:

1. Re-read the task's actual diff, commits, test output, pull request, and merge
   state. Do not infer completion from a task title or an old status note.
2. Append one entry using the template below. Record unknowns as `Not confirmed`.
3. Commit the entry with the work when practical, or point the coordinating task
   to the exact appended entry before handoff.
4. The coordinator reconciles the entry against current `origin/main`, GitHub
   pull requests, branch ancestry or patch equivalence, worktree cleanliness,
   and task status.
5. Only after that reconciliation may the coordinator archive the task and
   remove a merged or fully superseded branch/worktree. Never force-delete an
   unconfirmed branch.

## Entry template

```markdown
### YYYY-MM-DD — Task title

- Task: `TASK_ID`
- Branch/worktree: `BRANCH` at `ABSOLUTE_PATH`
- Outcome: Completed | Merged | Superseded | Blocked | In progress
- Commits/PRs: exact SHAs and links, or `Not confirmed`
- Validation: commands/checks actually run and their result
- Durable learnings: decisions, invariants, or techniques future tasks should reuse
- Failed approaches: symptoms, causes, and the safer correction
- Remaining follow-ups: explicit open work, or `None`
```

## Prune gate

A branch/worktree/task is eligible for cleanup only when all applicable answers
are yes:

- Is the worktree clean, with no Git operation in progress?
- Is every useful commit reachable from `origin/main`, or explicitly documented
  as patch-equivalent/superseded after diff review?
- Is the pull request merged or closed with no wanted commits left behind?
- Are required checks and release evidence recorded when the work affected a
  release?
- Has the owning task added or confirmed a learning entry here?
- Is the task idle/completed rather than actively writing to the worktree?

If any answer is no or unknown, retain the item and record the exact blocker.
